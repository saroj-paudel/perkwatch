# Perkwatch

Track every credit, free tier, trial and student perk you claim, and get Telegram reminders before they expire. Drop in a screenshot or paste an email, **Gemma 4** extracts the details, you confirm, and it is tracked.

> **Design principle:** plain code for everything that must be correct (dates, status, reminders); AI only to turn messy emails and screenshots into structured data. The AI never saves anything without your confirmation.

## Status

Pre-build. This repository currently holds the specification. The code is meant to be generated by a coding agent following `docs/09-BUILD-PLAN.md`.

## MVP features

- Sign in (single owner account, magic link)
- Upload a screenshot or paste email text, Gemma 4 extracts the perk, you review and confirm
- Manual entry fallback
- Dashboard sorted by expiry, with status, days left and value expiring soon
- Perk lifecycle: eligible, claimed, active, used, archived (expiring and expired are computed)
- Telegram bot reminders at 30, 14, 7, 3 and 1 days, plus claim-by reminders for unclaimed offers
- Telegram commands: `/expiring`, `/help`
- Optional demo feature: ask questions about your stored perks ("what expires this month?")

Screenshots are processed in memory and never stored.

## Tech stack

| Layer | Choice |
| --- | --- |
| Web app | Next.js (App Router), TypeScript, Tailwind CSS |
| Auth, database | Supabase (Auth, Postgres with row-level security) |
| AI | Gemma 4 through the Gemini API (`@google/genai`), server-side only |
| Notifications | Telegram Bot API (plain `fetch`, no library) |
| Scheduler | Vercel Cron (default) or Supabase `pg_cron` + `pg_net` |
| Validation | zod |
| Tests | Vitest |

## Prerequisites

- Node.js 20 or newer
- A Supabase project
- A Gemini API key from Google AI Studio
- A Telegram bot token from `@BotFather`
- (Deploy) a Vercel account, or any host that can call a URL on a schedule

## Quick start

```bash
# 1. Scaffold happens in Task 0.1 of docs/09-BUILD-PLAN.md.
#    After the app exists:
cp .env.example .env.local        # fill in the values
npm install
npm run dev                       # http://localhost:3000
```

Supabase setup:

1. Create a project.
2. Run `supabase/migrations/0001_init.sql` in the SQL editor (or with the Supabase CLI: `supabase db push`).
3. In Authentication, add your own user manually (Users, Add user), then turn **off** "Allow new users to sign up".
4. Set the Site URL to your app URL and add `<APP_URL>/auth/callback` to the redirect URLs.

Telegram setup:

1. Create a bot with `@BotFather` and copy the token and username into `.env.local`.
2. After the app is reachable on a public URL, register the webhook:

```bash
curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
  -d "url=$APP_URL/api/telegram/webhook" \
  -d "secret_token=$TELEGRAM_WEBHOOK_SECRET"
```

3. In the app, open Settings, press "Link Telegram", and tap the deep link it shows.

Gemma 4 setup: look up the exact Gemma 4 model ID in the Gemini API models documentation at ai.google.dev and set `GEMMA_MODEL_ID`. Do not guess it.

## Deployment

1. Push to GitHub and import into Vercel.
2. Add every variable from `.env.example` in the Vercel project settings.
3. `vercel.json` registers the daily cron for `/api/cron/remind`. Vercel sends `Authorization: Bearer <CRON_SECRET>` when `CRON_SECRET` is set.
4. Register the Telegram webhook against the production URL.
5. Run through the manual QA checklist in `docs/08-TESTING.md`.
